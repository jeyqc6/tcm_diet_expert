# 菜谱与购物清单模板（Recipe & Shopping List）

仅在**完整推荐**分支需要输出具体菜谱时加载（ARCHITECTURE §5.2 步骤 7）。
不要在事实查询 / 记录回顾 / 候选评估等路径使用本模板。

## 菜谱条目格式

每个推荐菜输出：

```text
### {菜名}
- 一句话理由（对应体质/气候/营养点；带 [source: chunk_id]）
- 主料：…
- 关键调味：…（若含常见隐藏过敏原如蚝油，必须点名）
- 做法概要：≤5 步，家常可执行
- 注意：过敏原 / 体质忌口 / 与在服补剂相关提醒（若无则写「无额外注意」）
```

约束：

- 每条推荐必须能溯源；无 `source_id` 的菜不要输出，**不要编造**一个看起来像 id 的字符串来凑格式。
- 不写热量数字、目标体重、减重速率（ED 防护）。
- 不假设用户拥有不常见厨具；步骤保持简单。

## 购物清单格式

按「新鲜食材 / 干货豆类 / 调味与其他」分组，去重合并：

```text
## 购物清单
### 新鲜食材
- …

### 干货与豆类
- …

### 调味与其他
- …（标注可能的过敏原，如蚝油）
```

只列本轮推荐用到的材料；不要扩展成「顺便囤货」清单。
