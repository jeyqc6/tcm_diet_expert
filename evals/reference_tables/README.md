## `constitution_season.jsonl` —— 体质 × 季节 参考表

**45 条 = 体质九分类 × 五季**(春 / 夏 / 长夏 / 秋 / 冬)

这张表填补了一个之前的缺口:E1(15 条单领域正确性)一直没有 ground truth。

### 怎么来的

由两张已有来源的表机械交叉推导:

- 体质基线方向 ← `knowledge/tcm/core-tables.md` §1(ZYYXH/T157-2009)
- 季节调养原则 ← `knowledge/tcm/core-tables.md` §4(五行—五脏—五季对应)

### ⚠️ `source_status: "derived"` 是什么意思

这是一个**新增的第三种状态**,不同于规则表的 `verified` / `needs_source`:

| 状态 | 含义 | 能否用作 ground truth |
|---|---|---|
| `verified` | 有一次来源,可直接引用 | ✅ |
| `needs_source` | 我的推断,没有来源 | ❌ |
| `derived` | **由两张有来源的表机械交叉得出,推导过程可复核,但组合结论本身未经专家确认** | ⚠️ 需专家抽检后方可 |

**为什么要区分**:说它是"推断"不准确(基线有来源),说它是"已核实"也不准确(交叉组合是我做的)。R1 防循环论证要求诚实标注证据链的每一环——这是第三种情况,必须单列。

**行动项**:找一位中医背景的人抽检 10-15 条,记录一致率。通过后改为 `verified`。这是 `planning/worknotes.md` R1 缓解措施第 4 条的具体落点。

### 字段

| 字段 | 说明 |
|---|---|
| `constitution` / `season` | 输入条件 |
| `direction` | **标准答案**:该体质在该季节的调理方向 |
| `recommend` / `avoid` | 具体食材,用于更细粒度的比对 |
| `rationale` | 为什么是这个方向 |

## ⭐ 交叉推导里发现的三类高价值场景

机械交叉之后浮现出一批**体质与时令不一致**的组合,这些恰恰是最该进 eval 集的——因为它们不能靠单一规则答对。

### 1. 内部张力(体质与时令方向相反)

| 条目 | 张力 |
|---|---|
| E1-14 阳虚 × 秋 | 体质要温,时令要润;一味温燥会伤津 |
| E1-18 阴虚 × 长夏 | 祛湿多用温燥,而阴虚忌温燥 |
| E1-24 痰湿 × 秋 | 燥湿与润燥方向相反 |
| E1-34 血瘀 × 秋 | 秋主收敛,与活血有轻微张力 |

**这四条是 E1 子集里最该收的**,因为它们要求模型同时持有两个约束并找平衡,而不是查表复述。

### 2. 反直觉场景(与常识相悖)

| 条目 | 反直觉在哪 |
|---|---|
| E1-12 阳虚 × 夏 | **夏天反而是阳虚质最容易受伤的季节**——生冷摄入激增 |
| E1-20 阴虚 × 冬 | "冬季进补"一律推温热,对阴虚质是错的 |
| E1-25 痰湿 × 冬 | 冬季进补会加重痰湿 |
| E1-30 湿热 × 冬 | 冬季温补对湿热质是反向操作 |

**这组测的是模型会不会被"冬天要进补"这类常识性先验带偏。** 通用模型很可能答错,是区分度最高的一组。

### 3. 强叠加(体质与时令同向放大)

| 条目 | 说明 |
|---|---|
| E1-23 痰湿 × 长夏 | 最强叠加,应提高干预强度而非维持常规 |
| E1-35 血瘀 × 冬 | 寒主收引凝滞,症状最明显 |
| E1-36 气郁 × 春 | 春应肝,完全一致 |
| E1-45 特禀 × 冬 | 火锅、年夜饭等成分不可控场景,全年最高风险 |

**测的是模型知不知道"一致"时该加强而不只是照常**。

## ⚠️ 特禀质的特殊性

E1-41 至 E1-45 五条的逻辑与其他八种体质**根本不同**:

> 其他体质的推荐逻辑是"**补什么**",特禀质是"**排除什么**"。

这五条的 `recommend` 字段刻意写得很空(只写"性平食材""已确认安全的常吃食物"),因为**对过敏体质给出具体食材推荐本身就是风险**。系统在这个分支上应当保守到近乎沉默。

对应 `docs/PRD.md` §8.3:该切片的过敏原阻断要求 100%,不接受 95%。

## `e1_retrieval_gold.jsonl` —— M1 检索金标（chunk id）

E1 的 **检索** ground truth。不改冻结的 `dataset.jsonl`。

每条有一组或多组 `groups`。组内 `any_of` 是等价 chunk（命中任一即可）。体质×季节题固定两组：**体质专章 + 节气表**（春 `tcm_000029` / 夏 `tcm_000030` / 长夏 `tcm_000031` / 秋 `tcm_000032` / 冬 `tcm_000033`）。不要把 `constitution_season.jsonl` 里的 derived 合成句当成必须召回的原文。

`retrieval_gt` 给可选的 LLM 检索裁判用，只写库里有的方向。E1-14 的「餐前后 1 小时」在 `conflict_rules.jsonl` S08，属于回答/规则评测，不在这个文件里。
