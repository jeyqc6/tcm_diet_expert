# 免责声明与降级模板

`docs/PRD.md` §10 输出拦截触发后使用。**模板化的目的是保证一致性**——同类情况每次都用同一句话,而不是让模型每次现编。

---

## 1. 症状类提问(High 风险档)

触发:用户提问涉及具体症状(疲劳、上火、失眠、便秘、痘痘等)

```
以下内容是传统食养参考,不构成诊断或治疗建议。
如果这个情况持续或加重,建议咨询医生或执业中医师。
```

**位置**:放在建议**之前**,不是末尾。放末尾等于没说。

---

## 2. 疾病 / 用药咨询(受限模式)

触发:用户提到已确诊疾病或正在服用处方药

```
你提到的情况涉及具体疾病/用药,这超出了本工具的范围。
我可以提供通用的膳食参考,但**不能替代主治医生的建议**,
尤其是在药物与食物可能存在相互作用的情况下。
```

**行为**:转入受限模式,只给通用信息,不给个体化推荐。

---

## 3. 药食同源物质

触发:推荐涉及药食同源目录中的物质

```
[X] 属于"按照传统既是食品又是中药材的物质"。
它有传统食养价值,但**不能代替药物治疗疾病**。
```

**来源**:多篇官方资料的固定表述,见 `knowledge/tcm/core-tables.md` §3。

---

## 4. 证据不足(诚实说不知道)

触发:检索为空、置信度低于阈值、或两侧都无依据

```
这一点我没有找到可靠依据。与其给你一个不确定的说法,
我更愿意直说:这个问题目前的证据不足以下结论。
```

**⚠️ 重要**:`docs/PRD.md` §9 明确规定——**恰当地说"不知道"在 eval 中计为正确**,不是失败。

---

## 5. 民间"食物相克"说法

触发:用户询问食物相克 / 发物 / 相冲

```
这个说法缺乏可靠的证据支持。
不过 [真实存在的注意事项],这一点确实值得注意。
```

**⚠️ 措辞要点**(规则 X01):既不确认未经证实的说法为真,也不因"没听说过"而否定用户顾虑。**把顾虑导向一个真实存在的、有依据的注意事项**,比单纯否定更有帮助。

---

## 6. 冲突未命中规则表(fallback 三段式)

触发:两侧结论冲突且规则表无命中

```
这个情况两套体系的看法不太一致:
- 中医角度:[立场 A]
- 营养学角度:[立场 B]

我先给一个双方都不反对的稳妥选择:[保守交集建议]。
```

**同时**:写一条进 `evals/conflict_gaps.jsonl`。

---

## 7. 特禀质(Critical 档)

触发:用户画像为 `te_bing`,或对话中出现过敏相关表述

```
你的画像里标记了过敏体质。以下建议已排除你已知的过敏原,
但**首次尝试任何新食材前,请先少量试用**。
如果有过敏史或曾发生过严重反应,请以医生的意见为准。
```

**行为约束**:对特禀质,推荐逻辑从"补什么"改为"排除什么"(见 `evals/reference_tables/README.md`)。系统在这个分支上应当保守到近乎沉默。

---

## 8. 成分不可控场景(外食)

触发:饮食记录为火锅、烧烤、外卖、餐厅高汤等

```
这类场景的具体成分我看不到(高汤、蘸料、共用油锅都可能含未标注的成分)。
下面的分析基于常见做法,实际情况可能有出入。
```

**依据**:`knowledge/food/README.md` §4;`knowledge/allergen/hidden-allergens-cn.jsonl` HA018、HA019。

---

## 9. ED 防护(用户索要数值目标)

触发:用户要求热量额度、目标体重、减重速率

```
本工具不提供热量或体重的数值目标——这类数字容易变成压力来源,
而且脱离个体情况的数字并不可靠。

我可以从另一个角度帮你:[定性方向,如"近期饮食偏肥甘厚味,
建议这周多用蒸煮、增加赤小豆薏米这类利湿食材"]。
```

**⚠️ 不要含糊敷衍。** 说明原因 + 给出替代方案,而不是简单拒绝。见 `docs/DECISIONS.md` D16。

---

## 10. 用户自述极低摄入 / 体重焦虑(最高优先级)

触发:用户表述中出现极端限制性饮食或明显的体重相关焦虑

```
听起来你最近在饮食上给自己的压力不小。
我先不给限制性的建议了——这种时候更重要的是有人一起看看情况。
如果你愿意,可以和信任的人或专业人士聊聊。
```

**行为**:**立即停止一切限制性建议**,不给食谱、不给方向、不分析热量。这条优先级高于所有其他规则。

---

## 使用原则

1. **模板是下限不是上限**——可以按语境自然表述,但核心信息一个字都不能少
2. **免责声明放前面**,症状类尤其
3. **不叠加**——一次回答里最多两条,堆多了用户会全部略过,反而失效
4. **不要道歉式开场**("很抱歉我不能……")。直接说边界在哪、能提供什么替代
